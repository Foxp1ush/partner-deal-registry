# 파트너 영업권 관리 v2

> 총판-파트너 영업에서 **"이 고객, 누가 먼저 잡았나"** 분쟁을 없애는 영업권(deal registration) 관리 도구.
> 2026년 재직 중 직접 만들어 운영했던 v1을 회고하고 **새로 설계한 버전**입니다. 모든 데이터는 가상입니다.
> 시연·내부 보고용 데모이며, 실제 운영에는 서버·보안·현장 검증이 더 필요합니다(아래 "운영 전에 할 일").

## 무엇을 하나
| 기능 | 설명 |
|---|---|
| 고객사 등록 | 명함·사업자등록증 이미지를 올리면 **AI(Claude)가 회사명·사업자번호·담당자를 자동 입력**. 사업자번호·명함·사업자등록증 중 하나는 증빙으로 필수 |
| 선점 판정 | ① 사업자번호 일치 ② 법인 표기를 뺀 회사명 일치 → 등록 차단 / ③ 이름이 비슷하면 AI 의견을 붙여 **총판 검토**로 |
| 90일 보호 | 가망 고객은 등록 시점부터 90일 보호, 만료 14일 전부터 알림, 지나면 자동 만료. 총판 연장은 횟수 제한 없이, 등록별·고객사 누적 연장 횟수를 표시 |
| 계약 고객 | 수주하면 **담당 파트너**로 기간 없이 유지. 라이선스(영구·1년 구독·3년 구독)별로 유지보수 연장·구독 갱신 시점을 알림 |
| 계약 금액 | 수주할 때 **계약 금액(공급가액) 필수**. 금액이 보이는 모든 곳에 **"공급가액, VAT 10% 별도"** 표시 |
| 영업 관리(CRM) | 고객사별 영업 단계(Stage 0~4 + 수주·보류·실패)·활동 이력. 기록은 수정·삭제 불가. 이관돼도 이전 파트너의 기록은 새 파트너에게 비공개(보존), 총판은 사유를 남기고 열람 |
| 기술 문의(티켓) | 파트너가 고객사 문의를 올리면 총판 엔지니어가 맡아 답변 → 파트너가 해결 확인(7일 무응답 시 자동 종료). 화면 캡처 첨부, 종료된 문의까지 검색 |
| 실적 통계 | **일·주·월·분기·년** 추이, 파트너(담당자)별 비교, 단계별 퍼널, 기술 문의 통계(분류별 수·평균 첫 답변 시간) |
| 이력 로그 | 등록·차단·승인·반려·이관·수주·문의를 모두 기록 → 분쟁 시 근거 |
| 계정·역할 | 회원가입 없는 초대 방식(총판 → 파트너 관리자 → 직원). 임시 비밀번호는 한 번만 표시, 첫 로그인 때 변경 강제. 프로필(직함·연락처 등)은 본인이 채움 |
| 총판 열람 통제 | 총판은 평소 집계만 보고, 상세 기록은 사유 입력 후 열람 → 기록이 열린 파트너 모두에게 열람 기록 공개 |

**설계 원칙**: AI는 판단을 *돕고*, 차단은 규칙이, 애매한 경우의 결정은 사람이 한다.

### 역할별로 보이는 메뉴 (왼쪽 메뉴)
| 역할 | 메뉴 |
|---|---|
| 총판 총괄 매니저 | 할 일(검토 대기·ENCY 계정 발급·만료 임박) · 영업(영업 현황·실적 통계·전체 현황·등록 관리) · 지원(기술 문의·공지 작성) · 관리(파트너·계정·이력 로그) |
| 총판 엔지니어 | 기술 문의 · 공지 |
| 파트너 관리자 | 공지 · 영업(고객사 등록·내 영업권·영업 관리·선점 조회) · 기술 문의 · 팀(팀 관리·총판 열람 기록·실적 통계) |
| 파트너 영업 담당자 | 공지 · 영업 · 기술 문의 (자기 담당 고객만) |

모든 역할에 '내 계정'(프로필·비밀번호)이 있고, 처리할 건수는 메뉴에 숫자로 표시된다. 총판 조치는 메뉴에서 숨길 뿐 아니라 서버에서도 총괄 매니저만 허용한다.

## 실행
```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
set ANTHROPIC_API_KEY=...        # 없으면 수동 입력 모드로 동작
.venv\Scripts\python.exe -m streamlit run app.py
```
- Windows에서는 `사이트 켜기.bat`을 더블클릭해도 된다(이 PC에서만 열리게 실행하고 브라우저를 연다).
- 처음 실행하면 `data/registry.db`에 가상 데이터(6개월치 이력 포함)를 채운다. 지우면 초기화.
- 시연용 계정(`seed.py`의 `DEMO_ACCOUNTS`) — 실제 운영 전에 반드시 바꾼다.

  | 역할 | 아이디 | 비밀번호 |
  |---|---|---|
  | 총판 총괄 매니저 | `admin` | `admin1234` |
  | 총판 엔지니어 | `engineer` | `admin1234` |
  | 파트너 관리자 | `partner-a` / `partner-b` / `partner-c` | `demo1234` |
  | 영업 담당자 | `a-sales1`, `a-sales2`, `b-sales1`, `b-sales2`, `c-sales1`, `c-sales2` | `demo1234` |
- 파트너 화면에는 다른 파트너의 이름·고객사명·실적이 보이지 않는다(선점 여부와 보호 만료일만).
- 환경변수: `CLAUDE_MODEL`(기본 `claude-opus-5-5`), `AI_DAILY_LIMIT`(기본 30회/일)

## 테스트
```bash
.venv\Scripts\python.exe -m pytest -q
```
95개: 선점 판정, 공개 범위, 권한(엔지니어·파트너가 총판 조치를 못 하는지), 상태 흐름, 날짜 규칙(90일 만료·7일 자동 종료), 기간 경계(분기·연도), 실적 합계를 확인한다.

## 배포 (Streamlit Community Cloud)
1. 이 폴더를 본인 GitHub 저장소로 push
2. share.streamlit.io → New app → `app.py` 선택, Advanced settings에서 **Python 3.13** (로컬과 같은 버전)
3. (선택) Settings → Secrets에 `ANTHROPIC_API_KEY = "..."` 입력. 없으면 AI 기능만 꺼지고 나머지는 동작
4. 데모 DB와 이미지는 앱이 재시작되면 가상 데이터로 초기화된다 (무료 서버는 파일을 보관하지 않음 — 실제 운영은 회사 자체 서버 전제)
5. 패키지 버전은 `requirements.txt`에 모두 고정했다. 특히 `starlette`는 1.x로 올리면 이미지가 깨진다
6. 시연용 명함의 한글은 `assets/fonts/NanumGothic-Regular.ttf`(OFL)로 그린다. 배경 이미지는 `assets/login_bg.*`(로그인 화면)·`assets/main_bg.*`(로그인 이후)이며 png·jpg·jpeg·webp를 쓸 수 있다. 없으면 배경 없이 동작

## 구조
- `app.py` — Streamlit 화면. 역할별 왼쪽 메뉴(`st.navigation`)와 각 페이지
- `matching.py` — 회사명 정규화, 사업자번호 검증, 중복 판정 (AI 없이 동작)
- `ai_extract.py` — Claude API: 이미지 추출, 유사 회사명 판단
- `db.py` — SQLite (파트너·등록·이력·계정·영업 기록·단계 이동·문의·공지)
- `auth.py` — 로그인 (비밀번호는 해시로만 저장, 퇴사·계약 종료 계정 차단)
- `accounts.py` — 계정 발급·관리, 총판 역할(총괄 매니저·엔지니어), 내 프로필
- `crm.py` — 영업 관리: 단계·활동 이력, 수주(계약 금액), 보는 범위, 직원 퇴사·인계, 총판 집계·사유 열람
- `admin.py` — 총판 조치 (승인·반려·해제·연장·이관·회사명 수정·반려 되돌리기, 충돌·권한 검사 포함)
- `evidence.py` — 등록 증빙 이미지 저장(줄여서 보관, 지우지 않음)
- `tickets.py` — 기술 문의: 상태 흐름, 담당 배정, 공개 범위, 자동 종료, 검색
- `stats.py` — 실적 통계: 기간 단위 계산, 추이·비교·퍼널·문의 통계
- `seed.py` — 가상 데이터 (사업자번호 앞자리 000 = 실존하지 않는 번호)
- `registry.py` — 등록 판정 흐름을 화면과 분리한 모듈 (실제 운영 대비용, 아직 app.py에 미연결)
- `WORKLOG.md` — 날짜별 작업 기록과 정책 결정 이유
